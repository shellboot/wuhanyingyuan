# 盈圆整站 WordPress 化设计稿

## 目标

将 `wuhanyingyuan-news` 当前的单页营销站、新闻列表、文章详情和自建后台，迁移为一套可部署在阿里云 ECS Docker 环境中的 WordPress 站点。整站内容由 WordPress 后台维护，前台保留现有品牌视觉、内容结构、移动端体验和 SEO 能力。

## 已确认范围

- 首页、新闻列表、文章详情、全站联系方式及首页各业务区块都由 WordPress 管理。
- 不使用当前的 Node.js 文件存储后台作为生产后台。
- 使用 WordPress 原生用户、文章、媒体库、草稿和发布流程。
- 预留第三方新闻发布工具接入能力，工具应通过 HTTPS 向 WordPress 创建、更新和发布新闻。
- 部署方式为 Docker Compose，适配 ECS 上的单个域名站点。
- 本阶段只完成设计稿和实施计划，不创建业务代码。

## 非目标

- 不保留 `/admin.html` 这套固定密码后台。
- 不把现有 JSON 文件继续作为生产数据源。
- 不在首期建设多语言、会员系统、在线支付、复杂表单工作流或独立移动 App。
- 不在首期把所有页面重做成 Gutenberg 可视化区块编辑器；内容编辑以清晰的 WordPress 后台表单和文章编辑器为主。

## 技术路线

### 方案 A：定制经典主题 + 独立站点功能插件（推荐）

主题负责现有页面模板、CSS、JavaScript 和品牌视觉；站点功能插件负责内容类型、字段、迁移命令和业务配置。新闻使用 WordPress 原生文章，首页重复区块使用自定义内容类型。

优点：

- 最容易按现有 HTML/CSS 精确还原。
- 内容模型明确，运营人员知道每个区块在哪里维护。
- 主题和业务数据解耦，后续换主题不会丢失内容类型。
- 不依赖付费页面构建器。

代价：

- 首页编辑体验是结构化后台表单，不是完全自由的拖拽编辑。
- 需要维护少量 WordPress 插件和主题 PHP 代码。

### 方案 B：原生区块主题

使用 `theme.json`、模板和区块模式重建页面。

优点：更贴近 WordPress 官方编辑方向。

代价：现有版式包含大量定制卡片、图标、轮播和锚点导航，完全用核心区块还原会显著增加样式覆盖和编辑误操作风险。

### 方案 C：Headless WordPress

WordPress 只做内容接口，另建前端应用。

优点：前端技术自由度高。

代价：多一套服务、构建和部署链路，不符合当前单站、低成本维护的目标。

## 选型

采用方案 A。生产内容结构由 WordPress 保存，主题只负责显示，迁移与初始化逻辑放入站点插件，避免把关键内容类型绑死在主题里。

## 信息架构

### WordPress 原生内容

- 文章：新闻资讯。
- 分类：行业动态、投放干货、平台政策等，具体分类由后台维护。
- 媒体：新闻封面、正文图片、首页图片、微信二维码。
- 页面：首页、新闻页及必要的站点说明页。

### 自定义内容类型

- 投放平台：名称、英文名、图标文字、说明、两项数据指标、排序。
- 服务内容：标题、图标、说明、排序。
- 服务优势：标题、图标、说明、排序。
- 合作流程：步骤标题、说明、排序。
- 客户案例：行业标签、标题、说明、两项指标、排序。
- 常见问题：问题、回答、排序。
- 数据效果图：图片、替代文本、排序。
- 成果数据：数值、说明、排序。

### 站点设置

- 品牌名称、Logo、微信二维码、联系电话、工作时间。
- 首页主视觉文案、主按钮文案、次按钮文案。
- 首页各区块标题与副标题。
- 关于我们正文、按钮文案、案例说明和数据来源说明。
- 全站 SEO 默认标题、描述、分享图和备案信息。
- 页脚版权文案。

## 页面与路由

- `/`：首页。
- `/news/`：新闻列表。
- `/news/<slug>/`：文章详情。
- `/news/category/<slug>/`：新闻分类归档，使用 WordPress 固定链接。
- 旧地址 `/news.html` 永久跳转到 `/news/`。
- 旧地址 `/article.html?id=<旧ID>` 永久跳转到对应新文章地址。
- `/admin.html` 不再提供；后台统一进入 `/wp-admin/`。

管理端与 C 端使用不同模板和权限边界：

- C 端只渲染官网主题，不接管 `/wp-admin/` 和 `/wp-login.php`。
- 管理端使用 WordPress 标准后台，必须登录后才能访问。
- 首期默认使用同域 `/wp-admin/`；若必须使用独立管理子域名，需要在部署前单独确认域名、证书和 Cookie 配置。

## 内容迁移

旧服务器若存在 `data/articles.json` 和 `uploads/`，按以下规则迁移：

- 标题、正文、摘要、创建时间、更新时间保留。
- 分类映射为 WordPress 分类。
- `published=true` 导入为已发布，`false` 导入为草稿。
- 封面和正文图片下载到媒体库并替换 URL。
- 保存旧文章 ID 到文章元数据，用于生成旧详情页跳转。
- HTML 正文经 WordPress 允许列表清洗，避免脚本和事件属性进入数据库。

若旧服务器没有实际数据，则初始化空新闻栏目和一组可编辑的示例内容。

## 第三方新闻发布工具接入

目标是让现有新闻发布工具直接向 WordPress 写入内容，同时把 WordPress 作为唯一内容源。工具的“支持 WordPress”通常表示其适配器会调用 WordPress REST API，但必须以该工具当前版本的官方接入文档为准。

### 首选接入方式

- 工具中的“网站框架”选择 WordPress。
- 域名填写正式站点根地址，例如 `https://www.wuhanyingyuan.com`，不带尾部 `/`。
- 内容写入使用 WordPress 原生 REST API `/wp-json/wp/v2/posts`。
- 鉴权使用 WordPress Application Password，不使用网站管理员登录密码。
- Nginx 必须将客户端的 `Authorization` 请求头传给 PHP-FPM，否则 Application Password 鉴权会失败。

### 截图字段的暂定映射

| 工具字段 | WordPress 配置 |
| --- | --- |
| 网站框架 | 选择 WordPress |
| 域名 | 正式站点根地址，不带尾部 `/` |
| `API_KEY` | 专用发布账号的用户名；若工具文档定义为插件生成的“发布 Key”，则按工具文档处理 |
| `API_PASS` | 专用发布账号的 Application Password；若工具文档定义为插件生成的“网站密钥”，则按工具文档处理 |
| 后台登录账号 | 同一个专用发布账号，用于人工排查和审计 |
| 备注 | 例如“生产站-盈圆官网-新闻发布” |
| 验证分类 ID | 新闻目标分类的数字 Term ID，例如“行业动态”分类的 ID |

`API_KEY` 和 `API_PASS` 是否直接对应 WordPress 用户名和 Application Password，取决于工具具体版本。若工具确实要求专属插件生成“发布 Key/网站密钥”，则增加仅覆盖发布所需的兼容插件，不把字段解释为管理员密码。

### 发布账号与权限

- 创建专用的“新闻发布接口”账号，不与超级管理员、站点所有者共用。
- 账号只保留 `read`、`edit_posts`、`publish_posts`、`upload_files`、`edit_published_posts` 等新闻发布所需权限。
- 禁止授予安装插件、切换主题、修改站点设置、管理用户或编辑代码的权限。
- Application Password 和工具密钥只保存在发布工具及必要的一次性配置过程中，不提交到 Git，不写入公开文档。
- 工具日志和部署日志不得打印明文密钥；怀疑泄露时立即撤销旧密钥并重新签发。

### 内容与幂等要求

- 发布工具创建的新闻使用 WordPress 原生文章、分类、特色图片和发布状态。
- 外部正文按 WordPress 允许列表清洗，不允许脚本、事件属性或未经授权的 HTML。
- 创建草稿时匿名用户不可访问；发布后新闻列表和详情页立即可见。
- 若工具支持外部文章 ID 或更新接口，应保存该 ID，重复推送时更新原文章而不是重复创建。
- 目标分类 ID 必须真实存在；接入工具前用 WordPress 分类查询或 WP-CLI 核实。

## Docker 架构

ECS 上使用以下容器：

- `wordpress`：基于官方 WordPress PHP-FPM 镜像构建，内置定制主题和站点插件。
- `db`：MariaDB，使用命名卷持久化。
- `nginx`：接收 80/443，提供 HTTPS 终止、静态资源缓存和 PHP 转发。
- `certbot`：首次签发及定时续期 TLS 证书。
- `wpcli`：按需运行的 WordPress CLI 运维容器。

持久化边界：

- 数据库使用独立 Docker 卷。
- `wp-content/uploads` 使用独立 Docker 卷。
- 主题、站点插件和部署配置进入版本库。
- 证书和私钥不进入版本库。

部署配置要求：

- `.env.example` 只放变量名和示例，不提交真实密码。
- `wp-config.php` 通过环境变量生成，开启调试时禁止公开展示错误。
- 固定 WordPress、PHP、MariaDB、Nginx 的稳定版本标签，不使用 `latest`。
- ECS 安全组只开放 22、80、443；WordPress 和数据库端口不直接暴露到公网。
- 站点强制 HTTPS，数据库和上传目录可持久化，容器重启后自动恢复。

## SEO 与可访问性

- 保留当前页面标题、描述、关键词、Open Graph 和结构化数据意图。
- 新闻文章输出文章结构化数据、发布时间、修改时间、封面和分类。
- 生成 sitemap 和 robots 规则。
- 统一 canonical 为正式域名。
- 保留跳转链接、键盘焦点、弹窗焦点管理和移动端导航可用性。
- 图片提供有意义的 alt，非装饰图片不在迁移时丢失。

## 安全与运维

- 禁止默认管理员密码和提交明文密钥。
- 限制文件编辑器和后台调试输出。
- 新闻作者使用 WordPress 角色权限，不共享超级管理员账号。
- 第三方工具使用独立发布账号和可撤销的 Application Password，不共享管理员凭据。
- 设置登录失败限制、HTTPS、安全响应头和数据库最小权限。
- 每日数据库备份，按保留周期备份上传文件。
- 提供备份恢复脚本、容器健康检查和部署回滚说明。

## 验收标准

- 首页、新闻列表、文章详情在桌面和手机宽度下与参考页面保持一致的布局层级和核心交互。
- 后台可以新增、编辑、发布、转草稿、设置分类和封面图，并立即影响前台。
- 第三方发布工具可以验证 WordPress 站点，正确写入草稿、发布新闻、设置分类和特色图片。
- 错误密钥返回明确的未授权响应，发布账号不能进入插件、主题和站点设置管理。
- 首页重复区块和站点联系方式无需改代码即可维护。
- 旧新闻 URL 可跳转到新地址，现有正文图片和封面不丢失。
- Docker Compose 在全新 ECS 环境中可完成安装、启动、重启恢复和 HTTPS 配置。
- 数据库与上传目录经过一次备份和恢复演练。

## 实施前需要确认

- 旧服务器是否仍有 `data/articles.json` 和 `uploads/` 可用于正式迁移。
- ECS 的操作系统、域名 DNS 管理位置、是否已有 80/443 端口占用。
- 管理后台是否接受同域 `/wp-admin/`，还是必须使用独立管理子域名。
- 第三方发布工具的名称、版本、官方 WordPress 接入文档，以及其是否要求安装专属插件。
- 首期是否需要接入第三方统计、站长平台验证码或 CDN。
