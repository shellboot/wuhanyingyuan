# 盈圆官网 WordPress 管理后台设计

日期：2026-10-29
状态：已批准

## 目标

把现有分散的盈圆内容管理功能整理成面向运营人员的“盈圆官网”入口，同时保留管理员维护 WordPress 所需的能力。

运营人员登录后应能完成官网日常维护：

- 管理首页首屏和各个内容区块
- 发布、编辑新闻并维护新闻分类
- 上传和使用图片资料
- 创建和管理仅用于新闻发布的账号

运营人员不能进入网站全局设置，也不能修改主题、插件、站点地址等可能影响整站运行的功能。

## 非目标

- 不另建一套独立 CMS 或独立管理后台
- 不改变现有首页和新闻页面的前台展示
- 不改变现有 REST API 的新闻发布方式
- 不修改数据库表结构
- 不通过直接修改 WordPress 数据库的方式隐藏菜单
- 不允许普通运营人员管理管理员或其他高权限账号

## 现状

现有盈圆核心插件已经注册了 8 个首页内容类型：

- 投放平台
- 服务内容
- 服务优势
- 合作流程
- 客户案例
- 常见问题
- 数据效果图
- 成果数据

这些内容类型当前都作为独立顶级菜单显示。盈圆设置也是独立顶级菜单。因此运营人员看到的是 WordPress 通用后台菜单和盈圆菜单混合的结构。

现有角色如下：

- `administrator`：管理员，拥有全部维护能力
- `yy_content_editor`：内容编辑，可管理首页内容、新闻和媒体
- `yy_publisher`：新闻发布接口账号，供发布工具通过 Application Password 调用 WordPress REST API

## 方案选择

### 方案一：在 WordPress 原生后台内重组菜单和权限

新增一个“盈圆官网”顶级菜单，复用 WordPress 原生新闻、分类、媒体和内容编辑页面，并针对运营角色精简其他菜单。

优点：

- 与现有插件、数据结构和发布 API 完全兼容
- 不引入外部插件或第二套后台
- 菜单和权限都能进入代码仓库，部署可复现
- 开发量最小，升级风险最低

限制：

- WordPress 原生侧边栏只支持“顶级菜单 + 一级子菜单”，不能原生呈现三级树
- 首页管理、新闻管理需要通过一个管理入口页组织其下功能

### 方案二：完全自定义品牌化仪表盘

制作独立页面统一展示首页各区块、新闻和发布账号。

优点：

- 最接近设计稿，可完全按运营流程组织界面
- 可以减少运营人员接触 WordPress 原生界面的机会

限制：

- 需要自行实现列表、编辑、上传、搜索和权限校验
- 后续维护成本明显高于原生后台
- 容易重复实现 WordPress 已有功能并引入权限或数据风险

### 方案三：安装第三方后台菜单编辑插件

使用第三方插件直接调整后台菜单。

优点：

- 初期配置较快

限制：

- 菜单配置通常只保存在数据库中，部署到新服务器后不能自动复现
- 插件升级可能改变行为
- 权限边界和隐藏菜单的可靠性依赖第三方插件

### 选定方案

采用方案一。保留 WordPress 原生后台能力，通过盈圆核心插件统一组织菜单和权限。管理入口页面只承担品牌化导航和快捷入口职责，不复制 WordPress 已有编辑功能。

## 后台信息架构

“盈圆官网”是唯一面向站点运营的顶级菜单。子菜单采用 WordPress 支持的两级结构：

```text
盈圆官网
├── 首页管理
├── 首屏内容
├── 投放平台
├── 服务内容
├── 服务优势
├── 合作流程
├── 客户案例
├── 常见问题
├── 数据效果
├── 新闻列表
├── 新增新闻
├── 新闻分类
├── 图片资料
├── 网站设置
└── 发布账号
```

其中：

- “首页管理”是品牌化入口页，显示各首页区块的用途和快捷链接。
- “首屏内容”进入现有首页文案设置页，该页面继续管理首屏文案和区块标题等共享文案。
- 8 个首页内容类型复用原有列表和编辑页面。
- “数据效果”是数据效果管理入口页，分别提供“数据效果图”和“成果数据”的列表及新增入口。
- “新闻列表”“新增新闻”“新闻分类”复用 WordPress 原生文章和分类页面。
- “图片资料”复用 WordPress 媒体库。
- “网站设置”仅管理员可见。
- “发布账号”仅允许管理 `yy_publisher` 发布账号。

管理员仍可看到 WordPress 原生菜单用于插件、主题、站点维护和故障处理。

原来的“盈圆设置”独立顶级菜单和 8 个内容类型顶级菜单会从顶部移除，其页面和内容记录继续保留。

## 角色与权限

| 功能 | 管理员 | 内容编辑 `yy_content_editor` | 发布接口账号 `yy_publisher` |
|---|---:|---:|---:|
| 盈圆官网入口 | 可见 | 可见 | 不可见 |
| 首页管理及各内容区块 | 可管理 | 可管理 | 不可管理 |
| 首屏及共享文案 | 可管理 | 可管理 | 不可管理 |
| 新闻列表、新增、分类 | 可管理 | 可管理 | 仅通过 REST API 发布 |
| 图片资料 | 可管理 | 可管理 | 仅通过 REST API 上传所需媒体 |
| 网站设置 | 可管理 | 不可见、不可访问 | 不可见、不可访问 |
| 发布账号 | 可管理 | 仅管理发布账号 | 不可见 |
| 外观、插件、工具、WordPress 设置 | 可管理 | 不可见、不可访问 | 不可见、不可访问 |

内容编辑不能获得 `manage_options`、`edit_users`、`promote_users` 等高权限能力。

发布账号管理使用独立的受限能力，不直接开放 WordPress 原生用户管理页面。

首页文案编辑使用独立能力，不与站点设置共用 `manage_options`：

- `yy_manage_homepage_settings`：编辑首屏、区块标题、联系区和关于文案
- `manage_options`：编辑品牌、联系方式、SEO、备案信息和站点级设置

管理员和内容编辑拥有 `yy_manage_homepage_settings`；只有管理员拥有 `manage_options`。

## 发布账号页面

“发布账号”页面只显示 WordPress 角色严格等于 `yy_publisher` 的账号，不显示管理员、内容编辑、多角色账号或其他用户。

允许的操作：

- 查看发布账号的显示名称、登录名和创建时间
- 新建发布账号
- 为发布账号生成 Application Password
- 重置发布账号密码
- 停用发布账号
- 重新启用已停用的发布账号

禁止的操作：

- 查看或编辑管理员
- 查看或编辑内容编辑账号
- 修改任意账号为管理员或其他角色
- 删除其他用户

Application Password 只在其生成时显示一次，不保存明文，也不能在之后重新查看。

停用发布账号后，该账号不能继续通过现有 Application Password 发布内容，但已经发布的新闻不受影响。实现时使用普通用户元数据记录启用状态，撤销已有 Application Password，并通过 WordPress Application Password 认证钩子拒绝已停用账号。升级前没有启用状态元数据的既有发布账号保持启用，避免部署后中断现有发布工具。

## 菜单行为

### 管理员

管理员保留完整 WordPress 菜单，同时看到“盈圆官网”入口。盈圆官网入口排在管理员常用维护菜单之前。

### 内容编辑

内容编辑登录后台后，默认进入“盈圆官网”的首页管理入口。

内容编辑只看到盈圆官网相关菜单。个人资料仍可从后台右上角进入，以便修改密码和查看自己的账号信息。

隐藏菜单后，仍需执行目标页面自身的能力检查。不能把“未显示菜单”当作唯一安全边界。

### 发布接口账号

`yy_publisher` 是 API 专用账号，不在后台显示盈圆官网菜单。若该角色意外登录后台，应重定向到个人资料或提示其使用发布接口，不能进入网站管理页面。

## 数据与兼容性

- 现有 8 个内容类型、分类、文章、媒体和选项数据保持不变。
- 现有新闻发布 REST API 路径和鉴权方式保持不变。
- 现有 `yy_home_settings` 和 `yy_site_settings` 选项结构保持不变。
- 通用 WordPress Editor 角色不在本次改动中自动精简；本次只调整 `yy_content_editor` 的实际使用角色。
- 角色版本号需要在插件升级后触发权限同步。
- 菜单调整只影响 `wp-admin` 展示，不改变前台路由和页面模板。

## 实施结构

菜单和后台体验放在盈圆核心插件的独立管理模块中，避免继续扩大现有设置文件。

职责划分：

- 菜单注册：创建“盈圆官网”、首页管理、新闻、媒体、设置和发布账号入口
- 内容类型注册：关闭 8 个首页内容类型的独立顶级菜单，由管理模块按固定顺序添加盈圆官网子菜单链接
- 设置页权限：首页文案使用 `yy_manage_homepage_settings`，站点设置使用 `manage_options`
- 角色同步：为管理员和内容编辑增加各自需要的新能力
- 发布账号：独立页面和服务端受限操作，不复用 `users.php`
- 后台精简：只对 `yy_content_editor` 和 `yy_publisher` 应用菜单隐藏与重定向规则

WP Admin 菜单只使用两级结构。需要三层语义的首页区块和新闻功能，由入口页组织导航，实际编辑操作继续使用 WordPress 原生页面。

## 安全边界

- “网站设置”继续要求 `manage_options`。
- 首页设置页面和 `yy_home_settings` 设置注册都要求 `yy_manage_homepage_settings`，防止页面可见但保存被 `options.php` 拒绝。
- 内容编辑不能修改主题、插件、WordPress 全局设置或其他用户角色。
- 发布账号页面必须在服务端校验目标用户角色，不能只依赖前端过滤。
- 所有表单提交使用 WordPress nonce。
- 所有输入执行能力检查、字段清理和输出转义。
- 账号密码和 Application Password 不写入日志、页面源代码或数据库明文字段。
- 隐藏菜单与页面权限检查同时实施。

## 失败处理

- 如果角色同步失败，管理员菜单仍可进入，现有 API 不受影响。
- 没有启用状态元数据的既有发布账号按启用处理，避免升级后中断发布；显式停用的账号拒绝认证。
- 如果 Application Password 创建失败，页面显示可理解的错误并保留账号，不显示半生成的凭据。
- 如果盈圆核心插件或管理菜单模块加载失败，按插件故障处理并保留服务器日志；不在运行中动态恢复多个独立顶级菜单。

## 验收标准

- 管理员后台同时存在“盈圆官网”和完整 WordPress 维护菜单。
- 内容编辑后台只显示盈圆官网相关菜单，以及右上角个人资料入口。
- 内容编辑可以管理首页内容、新闻、新闻分类、图片和发布账号。
- 内容编辑不能看到或直接访问网站设置、外观、插件、工具和 WordPress 全局设置。
- 发布账号页面不能查看或修改管理员和内容编辑账号。
- 新建发布账号可生成 Application Password，并成功调用现有新闻发布 API。
- 停用发布账号后，其 Application Password 不能继续发布新闻。
- 管理员仍可正常发布、编辑新闻和上传图片。
- 前台首页、新闻列表和新闻详情页面与改动前一致。
- 现有 PHP 静态检查和项目审计脚本通过。

## 实施边界

本设计不包含：

- 首页视觉样式调整
- 新增前台页面
- 新闻评论功能
- 多站点网络管理
- 第三方 SEO、缓存或表单插件接入
- 服务器和 Docker 部署方式调整
